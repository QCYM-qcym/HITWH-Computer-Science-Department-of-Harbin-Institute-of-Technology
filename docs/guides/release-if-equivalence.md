# 发布记录与既有 IF 输入的人工等价验收

日期：2026-11-06。本次在仓库外新建人工输入，检查[有界文件适配](release-file-adapter.md)的结果能否与既有输入流程衔接。完整验收和独立错误案例均已运行通过；没有读取真实载荷或既有模型权重。真实研究阶段与 Data Gate 不变。

## 核对的对象

一个预先固定的人工配方分别写出完整91列CSV和既有十字段JSON。两种文件各有独立的字节数与SHA，分别经过各自的正常读取流程。CSV走有界文件读取及磁盘聚合；JSON走既有记录CLI、输入CLI和带源重放的加载器。没有把CSV摘要写成JSON来源，也没有伪造已验算输入对象交给模型。

四个人工日期段各36分钟，共144分钟、576条记录。每分钟四种协议通道的手算13项特征为：

`[4, 10, 3, 100, 15, 1, 1, 1, 1, 1, 1, 1, 2]`

完整源读取凭据、原始分钟、当前输入、H15/H30增强输入、掩码、原因、预处理状态及训练/校准/测试资格逐项核对。H15有效84分钟，H30及共同有效24分钟；四段各6个共同有效分钟。训练位置为30—35，独立校准为102—107，测试评分为138—143。人工常量列经既有预处理后为零，不能将这个简单案例当作异常敏感性测试。

另用138行有变化的人工数值，独立计算log1p、总体标准差、历史median/MAD及选定残差，核对测试扰动不进入拟合和缺口后的历史重置。该项只验证数值流程，不执行模型。精确秒/微秒分位与全组重复排除另设CSV专用案例，不宣称它们与旧JSON记录身份规则相同。

## 实际 IF 运行

全部前置核对通过后，仅调用一次既有IF命令，在新的JSON输入链上拟合、评分、保存并执行其原有重放检查。配置固定为16棵树、6个训练样本、seed42，不做参数搜索。常量输入使每棵树保留未分裂的6样本叶；独立核对所安装实现的评分公式，预期异常分数及Q99均为0.5，绝对容差为`2e-15`。

24个共同有效位置的分数符合预期，其余120个位置分数和报警均为空。严格大于阈值的规则产生0个报警。测试标签人口为P_U的4正常/1攻击/1未知、P_B的5正常/1攻击/0未知、P_A的4正常/2攻击/0未知；三种口径的正常误报率为0、漏报率为1，precision为空。这些只是固定人工常量案例的算术答案，不用于支持模型有效性。

三个命令的实际进程身份、解释器环境、正常退出及回收均已核对。记录与输入命令各设30秒父进程超时，IF设120秒；本次没有触发超时。没有在此验收中建立通用进程树或操作系统内存隔离。

## 失败停止与结论范围

独立新目录中对CSV做等长内容修改，保留原预期SHA。聚合报`source_hash_mismatch`，没有返回成功分钟结果，临时库清理完成，记录CLI、输入CLI及模型均未运行。完整案例的两个源文件和冻结安装包的53个核心源码文件在验收前后保持一致。

本次证明固定人工CSV的预期分钟结果与已验算JSON链的IF输入相等。保存的IF包仍只绑定JSON来源；它不重放或认证完整CSV。当前产品没有新增CSV模型执行命令、CSV分钟包协议或真实数据准入。源钟面完成时间仍是可用时间代理，来源仍为`NOT_AUTHENTICATED`。

聚合计数、独立数值核对、模型实际运行与错误停止的详细证据见[验收记录](../research/2026-11-06-release-if-equivalence-verification.json)。真实预处理、训练、评分、阈值校准和正式模型比较继续标记`NOT_RUN`。
