# 从新目录重建候选人工演示

日期：2026-11-06。范围：`SYNTHETIC_ONLY / AUDIT_ONLY / ENGINEERING_TOY_ONLY`。这个入口用随安装包提供的固定人工记录，依次生成输入和四种方法的结果，再打开已有查看页面。它不接受真实CSV，也不代表数据Gate或研究效果通过。

## 准备与打开

先按[开发说明](development.md)安装锁定的核心和后端环境，创建一个用于存放演示的父目录。下面的 `.runtime` 必须已经存在；`demo-20261106` 必须尚不存在。可换成任意新目录名称，包括中文和空格，含空格的路径用引号括起。

```text
python -X utf8 -m traffic_api.candidate_demo_cli prepare --workspace .runtime/demo-20261106 --policy P_U
python -X utf8 -m traffic_api.candidate_demo_cli serve --workspace .runtime/demo-20261106 --port 0
```

第一条会执行固定人工IF、当前AE、H15历史AE和H30历史AE的训练与评分；第二条只读已有结果。`--policy` 必须显式给出 P_U、P_B 或 P_A，示例中的 P_U 仅是人工审计身份，不是最终标签政策决定。命令不会下载数据或依赖，不进行参数搜索。

准备时会依次输出 records、inputs、if-current13、ae-current13、ae-history15、ae-history30 的开始和完成事件。最终 `COMPLETE` 索引只在六阶段及保存关系核查全部成功后写入。查看命令给出系统分配的本机URL，打开该地址即可选择四个固定运行并查看[完整测试评价](candidate-evaluation-view.md)和[同条件方法对照](candidate-comparison-view.md)。只监听127.0.0.1，不自动打开浏览器。

停止查看后，重新执行第二条即可恢复；不必再次prepare。只检查结果而不开网页时使用：

```text
python -X utf8 -m traffic_api.candidate_demo_cli verify --workspace .runtime/demo-20261106
```

verify会核查保存关系，包括原阈值和评价的一致性；它不导入模型库、反序列化模型或重新训练。serve同样只读，启动阶段核查后由HTTP返回固定快照。

## 产物与失败处理

新目录包含固定 `source.json`、records三文件、inputs三文件、四个运行包各五文件以及 `demo.json`，共28个文件。随包源与既有人工夹具逐字节一致；索引只保存固定布局版本、源摘要、政策与四个运行身份，不接受任意路径。索引不是模型来源认证。

已有目录会直接拒绝，不覆盖、不恢复部分阶段。失败或中断会保留本次目录，提示“保留本次目录；换新目录重新准备”，不继续后续阶段。完成索引写入失败时撤销本次新建的索引，保留已有阶段产物。不要手工把失败目录改为COMPLETE，也不要替换其中单个运行包。

每阶段用同一解释器启动一个直接子进程，最多等待120秒；超时或中断后终止并回收，必要时kill。清理等待另计，不把它写成总720秒或任意第三方进程树保证。阶段原始输出不直接透传，错误使用固定code，阶段执行失败时附阶段名；help无需创建目录或加载模型。

prepare的错误和中断均返回2，成功返回0；serve的服务生命周期沿用[原启动器](candidate-viewer-launcher.md)。无人值守核查可加 `--shutdown-after-seconds 30`，表示服务就绪后请求正常停止，不是总执行时间硬上限。操作系统信号与定时停止的实测状态分别记录。

## 固定身份与只读恢复

verify把最终比较报告的政策、四个slot对应的run_id和固定源摘要与演示索引核对。serve在已有启动器的快照加载之后核run_id、政策、已核源摘要和来源状态，并在唯一一次比较之后核slot对应关系，再创建应用和监听。H15/H30互换归属，或政策、运行身份、固定源不符的自洽包替换，都会被拒绝。索引不绑定某一次权重版本，也不认证模型执行；身份相同的结果仍由原保存关系验证器检查。

启动前另有少量有界索引/manifest身份检查，不宣称全流程单次读取；完整运行加载和比较仍只委托原启动器执行一次。普通候选启动命令不带这些程序内约束时保持原行为。文件变化不热更新，必须停止并重新准入。

## 实际验收与限制

安装包在仓库外的中文空格新目录中完成六阶段准备，得到144个人工分钟、576条人工记录、24个共同有效分钟、拟合和校准各6分钟及四个完整运行包。verify、比较、HTTP及浏览器相符；原全漏报负例和precision未定义保留。第15分钟H15已可用、H30仍在预热，因此共同分数仍未提供。

全量Python在slot归属修复前为1710项及56子测试通过、2项符号链接权限跳过。独立审查发现H15/H30归属对调仍可serve，补失败回归并修复后相关108项通过，独立窄复审11项通过。修复只涉及serve身份约束，prepare/verify/清理函数体保持；重新安装最终17个源码/资源文件并复验已有目录，未为此重训。前端源码未变，沿用上一批120项结果，不称本批重新执行。

实际故障探针使用已生成目录的副本：损坏评价文件时verify/serve均拒绝，原目录保持。受控真实子进程配合注入Python中断，确认只开始首阶段、实际子进程结束、失败目录保留且没有COMPLETE；它不是一次真实键盘Ctrl+C测试。正常停止和只读再次打开按实际验收记录另列。

这些观察来自已有锁定依赖环境，不证明异机或全新联网安装。完整人工模型测试、只读验收、真实数据研究分别记录；真实预处理、模型训练评分校准和正式比较继续NOT_RUN。具体结果见[演示验收记录](../research/2026-11-06-candidate-demo-verification.json)。

本轮两次实际服务均正常定时停止、退出0、回收且端口关闭；第二次直接复用已准备目录，28个新文件身份保持。两次verify和两次serve均在独立受控进程中监测模型/生产模块导入及演示阶段调用，未发生禁止调用；允许既有保存关系复算。39个旧人工文件身份也保持。
