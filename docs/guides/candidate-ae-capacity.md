# 当前与历史 AE 的参数数量对照

日期：2026-11-06。用途：固定人工样例的工程对照。核心计算、保存、只读验算与独立比较已通过分项测试、独立复审及安装后实际验收。下午恢复后的验收于15:11完成，不记作原12:00截止前完成。真实数据训练、正式模型比较和效果结论仍为`NOT_RUN`。

## 对照内容

原[当前与历史AE](candidate-ae-synthetic.md)使用相同的隐藏层宽度，但输入维度不同，参数量也不同。本次保留它们，另加一个固定当前模型：

| 模型 | 输入维度 | 固定网络 | 参数量 | 用途 |
|---|---:|---|---:|---|
| 原当前AE | 13 | 13→8→3→8→13 | 288 | 与历史模型保留相同隐藏层宽度 |
| 新当前AE | 13 | 13→14→3→14→13 | 492 | 与历史模型作参数数量较接近的对照 |
| 历史AE，H15或H30 | 26 | 26→8→3→8→26 | 509 | 使用当前特征及对应历史偏离 |

492与509相差17，以509为参照约3.34%。隐藏宽度14在查看结果前固定，不搜索架构、不按检测效果选择；5%只是预先约定的数量接近说明。不同网络的有效容量、优化难度与分数尺度仍可能不同，不能据此直接把结果差异归因于历史信息。

新当前模型仍使用共同有效分钟，包括H15/H30的历史资格；不会额外取回当前模型本可使用的预热分钟。预处理仅沿既有已验算状态，固定CPU、seed42、5次全批Adam更新。当前13维重构误差经float64计算，历史误差通道为空且不适用。各模型使用共同独立校准人口中自身分数的linear Q99，严格大于才报警。

## 固定源执行

新增profile为`c17-i1-g13u-ae-current-capacity492-synthetic-v1`，仅支持`current_ae`且不带历史窗口。省略`--model-profile`仍使用原profile，原网络和默认配置不变。执行示例中的上游须由固定人工源生成并通过原有源重放：

```text
python -X utf8 -m traffic_anomaly.candidate_ae_cli --records .runtime/toy-records --inputs .runtime/toy-inputs --source-fixture tests/fixtures/g13u-records-v1.json --method current_ae --model-profile c17-i1-g13u-ae-current-capacity492-synthetic-v1 --run-id toy-current-capacity492-v1 --output .runtime/toy-current-capacity492-v1
```

新profile限定现有人工夹具的213497字节及SHA-256 `6f42399eabb07dc218eac19f4d648e57eb360a0c7167968ca1770733ea8649b2`。实际加载器先核源内容、重放与上游绑定，再核这个固定身份，之后才允许新建输出和执行模型。更换路径但字节相同可以；即使只增加换行、并为它重新生成自洽上游，也不能用于新profile。这个限制识别固定字节，不认证采集或训练来源。

输出仍为原五文件布局与JSON权重。外层profile、完整配置、配置SHA和实际权重形状必须相符；不能用一个参数量或输入维度代替完整检查。输出目录必须全新，不覆盖、恢复或修改旧包。

## 保存后只读验算

沿用[AE验算命令](candidate-ae-run-verification.md)。新profile必须提供原人工源，返回专属`c17-i1-g13u-ae-capacity-run-verifier-v1`；旧profile的可选源行为保持。

```text
python -X utf8 -m traffic_anomaly.candidate_ae_verify_cli --run .runtime/toy-current-capacity492-v1 --records .runtime/toy-records --inputs .runtime/toy-inputs --source-fixture tests/fixtures/g13u-records-v1.json
```

只读验算检查五文件、实际摘要、JSON权重形状、共同资格、保存分数、阈值和三种审计政策的算术关系，不导入Torch、不重建网络或复现训练。成功表示保存关系一致；模型来源仍未认证，训练与模型分数重放仍未检查。执行时新模型的当次重放与之后的只读验算分别记录。

## 保存结果的独立对照

容量对照使用独立命令，接收2至4个AE运行目录。必须包含新492当前模型和至少一个历史模型；原288当前模型、另一个历史窗口可以缺席，输出会明确列出缺项。各目录必须对应同一人工源、上游产物、完整分钟资格轴及训练和校准索引；只有样本数相同不足以放在一起比较。

```text
python -X utf8 -m traffic_anomaly.candidate_capacity_compare_cli --records .runtime/toy-records --inputs .runtime/toy-inputs --source-fixture tests/fixtures/g13u-records-v1.json --ae-run .runtime/toy-current-capacity492-v1 --ae-run .runtime/toy-history15-v1
```

输出依次保留原当前288、新当前492、历史H15、历史H30四个位置。每个已提供模型展示自身的阈值、保存的指标及不可计算原因；不同模型的分数和阈值不据此排列高低。比较只核保存关系和共同资格，不加载模型、不重新评分，也不证明各运行实际采用了其声明的训练过程。运行环境声明不一致时会明确记录差异，不能称为一致。

输出为有界JSON，包含末尾换行在内最多1 MiB。命令成功前会核验结构、计数及空值适用条件；不提供源文件、缺少必要对照、重复目录或槽位、混入IF、上游或资格不一致均拒绝。各模型仍使用自己的阈值；比较工具不重新选择阈值或计算新的研究评价。

专用HTTP与网页查看入口仍为`NOT_RUN`。新profile不能放入旧IF＋三个AE的经典四槽，也不自动获得旧曲线、单分钟详情或demo支持。生产134/268维契约与真实Data Gate不因这些人工入口改变。
