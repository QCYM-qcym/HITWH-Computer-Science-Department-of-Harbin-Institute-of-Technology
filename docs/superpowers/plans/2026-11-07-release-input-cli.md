## 范围和依赖

方案采用既有包接口的薄CLI，仅新增release_input_cli.py及其测试；不改包公式、pyproject、依赖、旧candidate或生产入口。raw包生成CLI与view后置并单独接受。前置是raw/prepared本地工程接受，不要求Desktop可用才继续可逆开发；提交推送仍只能Desktop。

命令为prepare、inspect、verify，显式政策/epsilon；固定H15/H30和13/26维。prepare拟合人工预处理，inspect仅保存检查，verify只重放保存参数。64KiB完整JSON、固定安全码、实际退出和残留记录是验收条件，不以main返回值替代OS观察。

## T5的实际接缝与预算

复用已验收A/B人工raw包，固定P_U、epsilon1e-6、H15/H30/fit30。新冻结、新离线wheel、新目标安装；没有新CSV聚合、独立参考重算或模型。第二轮十例为3次普通成功、5次普通预期拒绝和2次fresh受控main；构建pip、两个backend、安装pip共4次另计。

普通成功：prepare→inspect→verify，核原始stdout/退出、同一summary与新manifest实际身份。负例：缺epsilon、已有output、缺完成标记副本、错绑raw B、关闭读端断管。P1禁止raw/数值入口；P2允许保存参数重放但禁止refit。探针绑定定义模块及CLI别名，守卫保持至产品退出处理之后；普通8次不宣称同样被动作监测。

每案例60秒含10秒回收；构建/安装各120秒含20秒回收；监督每日志1MiB、目录256MiB，CLI单条输出另限64KiB。这些是受监督固定人工验收范围，不是库硬实时、OS写前或RSS限制。

## 首轮失败与修复

第一轮S1—S3/N1—N4通过，N5实际退出120而非2，stderr109字节含解释器退出flush错误；父进程退出1，P1/P2和最终成功保持检查未运行。原失败、安装与现场保留，没有修改期望或使用-u绕过。

窄修仅模块入口非零返回后的可用标准流描述符重定向；main保持宿主语义，正常SystemExit而非os._exit。新增回归、独审后重新冻结与安装。第二轮N5正常回收实际退出2，stderr精确25字节错误JSON，无附加诊断；其余9例及保持检查通过，父进程实际退出0。两个版本的证据与结果分开，不是自动重试。
