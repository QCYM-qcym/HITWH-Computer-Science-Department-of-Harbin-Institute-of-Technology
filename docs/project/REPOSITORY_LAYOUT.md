# 仓库文件管理

用途：分区与单一维护入口。修订2026-10-11；状态：维护规则。适用公开资产；依据本轮维护要求与PRIVACY。原始材料/历史不批量迁移删除。

| 分区 | 放什么 | 如何维护 |
|---|---|---|
| docs/project | 规划、发布规则和维护记录 | 当前状态只有一个权威入口，变化追加记录 |
| docs/requirements（规划） | 当前需求、RQ、追踪 | REQ-01对齐后建立，旧RTM留baseline |
| docs/design（规划） | 当前架构、数据、接口与详细设计 | 有实际材料才建立，候选/已采用分开 |
| docs/reports | 当前报告和答辩文本 | 保留版本，不覆盖历史原稿 |
| docs/baseline | 既有需求、研究、概要设计与验收材料 | 按原主题目录归档；较早方案不自动升级为最新决定 |
| docs/research | 文献核验与项目调研 | 保留来源和核验日期，候选与已复现明确区分 |
| docs/figures | SVG 图形源文件 | 按图集版本分目录，修改保留源文件 |
| docs/guides（规划） | 环境、运行、部署、复现/交付清单 | 实现后给真实入口，缺条件说明 |
| src | 检测核心、后端、前端 | 后续按模块建立独立依赖与入口 |
| tests | 数据边界、检测核心、接口和集成测试 | 测实际契约与泄漏边界 |
| configs | 默认配置与环境变量示例 | 真实凭据只放本地 |
| experiments | 实验协议、索引与可公开摘要 | 大体积运行目录本地保存 |
| data | 数据来源、版本、获取与校验说明 | raw/processed内容本地保存 |
| tools | 可复用维护工具 | 可运行入口与历史草稿明确区分 |

## 本地原稿与发布副本

当前本地 `docx/`、`research/`、`.knowledge-tools/`、知识库、第三方技能仓库及目录联接保留原状，不进入公开仓库。公开 Markdown 副本从原稿整理，文件名、正文和链接移除个人标识及本机路径。未检查的二进制原稿不入库。

旧生成脚本多依赖固定个人路径、外部模板、隐藏缓存及特定版本输入，暂保留本地。后续将实际要复用的脚本改成接收路径参数的独立工具，再进行隐私检查并纳入 `tools/`。这些脚本与尚未开发的检测业务源码分别管理。

新技术文档直接写入 docs；新业务程序直接写入 src。需要保留个人信息的学校提交原稿写入本地原稿目录，并另行生成公开版本。不要将第三方工具缓存或整份文献PDF复制进项目源码分区。

## 命名与归档

公开副本与原稿版本对应见[文档导航](../README.md)，私人路径映射只放忽略的本地配置。文本抽取不代表Office排版/图片/备注/隐藏内容已审阅；原生图形留本地，公开SVG按图集版本对应。

迁移同步链接、脚本路径和引用；不填空业务目录。状态唯一源[status.json](status.json)，任务[ROADMAP](ROADMAP.md)，风险[RISKS](RISKS.md)，差异/决定[DECISIONS](DECISIONS.md)，复核[MAINTENANCE_LOG](MAINTENANCE_LOG.md)。历史用Git/baseline索引，普通修订不复制“最终版”。

技术目录采用稳定英文名，正文与文件说明使用中文。历史文档沿用中文主题与版本号。实验运行标识建议 `YYYYMMDD-HHMMSS-方法-配置`，记录提交号及配置摘要。新归档保留原版本号，禁止通过批量覆盖抹去历史决定。
