# Data Gate 后的研究协议选择说明

日期：2026-10-22。状态：**C方向已获用户确认 / 具体数据与表示待审计决定**。用途：供项目负责人及导师审阅验证目标与数据路线。2026-10-22用户明确选择“C：优先核查替换主数据，保留误报—漏报核心问题；具体数据和表示审计后再定”。这项方向决定不替代[当前需求](../requirements/current-requirements.md)、报告V0.40或既有标签政策。依据：[上轮审计](DATA-GATE-2026-10-21.md)、[本轮增量证据](../research/2026-10-22-data-gate-evidence-update.md)、[当前契约](../design/contracts-v1.md)。

## 需要决定的问题

报告V0.40的核心问题是：近期历史能否减少正常分钟及正常高负载分钟误报，同时避免增加攻击漏报与成本。当前作者测试全段正常候选为0，任何共同有效分钟子集的正常分母也只能是0。时区或许可澄清不会改变这个事实；解释blacklist全覆盖的原因也不会自动生成正常样本。

作者训练全段的2,874个正常候选集中在末尾，不能证明三个开发区段各有足够正常样本，更不能证明覆盖多种正常动态。训练、模型验证和独立校准必须保留时间顺序，并分别扣除预热及缺口；本轮不代填日期或沿用旧比例。

**若仍保留V0.40核心问题，且不要求UGR16承担正式性能证据，推荐优先选择C的可行性阶段。** 先审计候选能否同时提供正常和攻击评价，再决定主数据及表示迁移；候选尚未证明适用。C可以避免B长期维护两套实验，也不继续等待UGR16零正常分母被时区或许可说明“解决”。若必须保留UGR16正式实验线且资源允许，选B；若接受核心问题收缩并希望减少新增实现，选A。已有代码投入不构成继续使用不适用数据的理由。

| 决策维度 | A：现数据、现标签政策 | B：增加独立评价数据 | C：更换主数据 |
|---|---|---|---|
| 1. 研究问题 | 收缩为历史输入对四类主要攻击检出、持续片段漏报及成本的影响；背景报警率仅为待批准补充 | 在补充数据内检验误报—漏报权衡，UGR16另做攻击侧案例；分别报告 | 在通过审计的新主数据内检验原误报—漏报问题，重新界定网络场景与攻击类别 |
| 2. 能支持的结论 | 仅限已核验测试范围、共同有效攻击分钟的检出表现与成本；待实测后才作判断 | 各数据集各自条件下的结果；若补充数据同时有正常和攻击，可在该数据内评估权衡 | 新主数据场景下历史表征的效果与限制；正常高负载须有可解释计数及足够分母 |

| 4. 四段设计 | 保留作者测试全段；前段顺序切成训练/验证/独立校准，逐段核正常及连续历史供应，空校准拒绝 | 每个数据集独立四段、拟合器、模型和阈值；各自遵守官方测试范围，若不兼容则另提划分决定 | 先查作者划分和时间结构，再冻结新四段；不得随机打散或按测试效果选区间 |
| 5. 指标及分母 | 攻击召回/漏报有条件可计算；正常FPR与高负载正常FPR均null。Precision/F1可能算术可算但退化，见下表 | 补充集有正常才有FPR；有正常与攻击才可解释完整混淆指标；各集分别计数，绝不合并分子分母 | 需先证明正常和攻击分母及覆盖；不满足的指标仍null，不能以换数据保证可计算 |

| 8. 迁移依赖 | A-1目标决定→A-2时区许可→A-3四段供应→A-4冻结参数→A-5IF工程验证→A-6缩窄实验 | B-1元数据筛选→B-2审计授权及有限样本→B-3新协议/维度决定→B-4适配与四段→B-5各集IF验证→B-6分别实验 | C-1主数据替换决定→C-2审计→C-3报告/契约迁移→C-4适配及回归→C-5IF验证→C-6新主实验 |

## 指标必须说明分母

令V为同一数据、同一测试范围内所有比较方法/窗口的共同有效分钟；N为标签政策下正常候选，A为主要攻击并集，B为仅背景。三类互斥，缺失标签另计。下面是待运行指标定义，不是本轮实测结果。

| 指标 | 分子 / 分母 | 当前UGR16的限制 |
|---|---|---|
| 正常FPR | V∩N中报警数 / \|V∩N\| | 分母0，null并保留原因 |
| 正常高负载FPR | V∩N∩高负载中报警数 / \|V∩N∩高负载\| | 正常分母0且流计数口径待核，null；分组阈值只能来自训练正常候选 |
| 主要攻击Recall | TP / (TP+FN)，分母为\|V∩A\| | 原始攻击932不是最终分母；须扣共同无效/预热并报告覆盖；分母0仍null |
| 各类攻击Recall | 该类在V中的报警分钟 / 该类在V中的分钟 | 多标签类别可重叠，不能把四类分母相加代替攻击并集 |
| Precision | TP / (TP+FP) | 当前N为空，FP=0；TP>0时数值为1，TP=0时null。不能据此称无误报或高精确率 |
| F1 | 2TP / (2TP+FP+FN) | 当前FP=0，可退化为2TP/(2TP+FN)；不是完整误报—漏报权衡证据；分母0时null |
| 漏报比例 | FN / (TP+FN) | 同Recall分母；不以point-adjust扩展报警 |
| 背景报警率（候选新增） | V∩B中报警数 / \|V∩B\| | 背景原始26,765不是最终有效分母；不含攻击重叠分钟，不能称FPR或正常性能 |
| 覆盖与成本 | 正常/攻击分别报告有效数与原始数；时间/内存绑定同一输入和资源条件 | 正常覆盖总数0仍如实列计数；运行成本不证明检测有效性 |

现有代码按既定公式计算Precision/F1并无因此发现的实现错误。未来报告需解释单类评价的退化含义；本轮不把有分母的数值擅自改为null。当前契约只有总体背景分钟计数，尚无背景报警率分子/有效分母字段；若选择增加，主控先确定独立字段、原因及版本，同步CLI/API/页面/导出，不能借用fpr字段。

同一补充集若只有正常数据，只能支持该模型在该集上的FPR；无法同时验证漏报代价。UGR16召回与补充集FPR必须分表，不能拼接成整体FPR、Precision或F1。各数据独立训练与校准只属于独立评价。若要评价泛化，需另定源/目标域、目标标签与校准可见性，并明确目标域是否允许重新拟合。

独立校准正常分数的99%分位点不保证未来测试FPR为1%，不能代替留出正常评价。当前UGR16开发范围没有主要攻击；若后续A/B中用它选型，须预先登记仅基于正常稳定性等开发证据的选型规则及限制，不借测试攻击选择窗口或模型。

## 补充或替换数据的准入清单

候选必须提供可定位的机构/作者发布版本及获取说明；原始载荷、衍生特征和标签分别有适用许可。时间戳单位、时区/DST与桶端点须足以支持真实连续H分钟，标签需与同一时间基准对齐。标签缺失或“未注入攻击”不能自动等同可靠正常。

需有足够连续的正常数据，分别支持模型训练、参数验证、独立校准和留出测试。每段都列原始数、正常/攻击/背景/未知数及共同历史有效数。单纯总行数大不证明99%分位阈值稳定；最低供应量、代表性和不确定性说明应在看测试效果前确定。正常动态/高负载的覆盖必须有数据证据；不能从实验室工作日安排推定生产网络日周期。

新特征要登记名称顺序、单位与聚合算法，核对负值/缺失/重尾及预处理适用性。UGR的log1p计数变换不能直接套用未知统计量。优先检查可合法取得的时间有序特征和少量样本；全量载荷大小、解压空间与CPU资源另核，不以云平台允许下载等同本机可执行。

流级完整统计量通常依赖流结束后的信息；新适配必须认证实际可获得时刻，不能把完整流统计放回流开始分钟而声称因果输入。跨桶流及分钟标签如何聚合须单列规则，停采区间与空桶也须区分。数据标为BENIGN不能靠填补不存在的八标签列来伪装成UGR的“八零正常”。

本轮仅筛选两个官方元数据候选，结果见[增量证据中的候选表](../research/2026-10-22-data-gate-evidence-update.md#补充或替换数据的有界筛选)。候选状态均为METADATA_ONLY；无已选数据、无样本审计，也没有通过Gate。
