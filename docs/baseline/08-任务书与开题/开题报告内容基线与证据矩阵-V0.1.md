# 开题报告内容基线与证据矩阵 V0.1

工作题名：**面向动态网络环境的时间感知流量异常检测方法研究**。

本文整理开题所需的背景、研究问题、实施方案与证据。它是供讨论的内容草案，不替代学校正式开题模板，也不冻结主数据集、模型或方法。论文与代码入口已经形成可追溯资料池；本课题尚未下载数据、训练模型或取得实验结果。已有需求与概要设计文档保留。引用池、单篇核验边界及待补字段见 Literature Matrix V1（原始附件保留本地）；代码借鉴见 GitHub项目借鉴清单（原始附件保留本地）。

## 1 选题来源与研究背景

本课题来源于对网络流量异常检测在动态正常背景下表现的关注。网络使用量和行为组合会随时段、工作日、业务安排等变化；正常背景本身也需要分析，不能简单把“大流量”当成攻击。UGR’16以评估周期性网络检测为目标，为研究时间背景提供了具体数据线索；其衍生特征版本又存在训练背景和数据质量差异，因此是否适合本课题仍需数据审计。[UGR’16原始论文](https://doi.org/10.1016/j.cose.2017.11.004)、[特征数据作者仓库](https://github.com/josecamachop/UGR16_FeatureData)、[数据质量后续论文](https://doi.org/10.3390/data10030033)。

以校园视频网站业务高峰为理解场景：某晚正常视频访问增加，系统的任务是根据已知历史和当前行为特征，判断这种变化是否仍符合正常背景；同一时段发生的扫描或异常连接，应在数据提供相关特征与标签时继续被识别。这个场景解释研究目的，不能当作B站真实流量实验，更不能假定公开数据能识别具体网站或校园学生。本课题使用公开数据，不采集B站内部数据，也不据聚合异常分数追查具体个人。

固定训练的模型是否产生更多误报，是待检验假设。时间建模、动态阈值和漂移适应均已有研究，不能据上述场景宣称本课题首先提出时间感知。开题需把对象、协议和比较条件限定清楚，再判断可能贡献。

## 2 研究目的

本课题拟在保持时间顺序、阈值预先校准的条件下，研究加入可解释时间上下文后，网络异常评分及误报行为是否改善。重点观察不同正常负载时段的FPR，同时记录异常召回、综合检测效果和运行成本，防止通过减少报警总量掩盖漏报。

当前拟验证的最小对象为UGR16 FeatureData的**一分钟聚合记录**，每条记录对应该分钟的特征向量；它不是一条连接、一个包或一个主机。若最终采用其他版本或流级数据，必须同步修改检测单位、标签定义和评价方式。目标不是建设生产级实时网络防御平台，而是形成可重复比较的方法实验和可回放原型。

## 3 理论与实际意义

研究意义在于区分模型表示、时间上下文和阈值选择的作用，并在一致协议下给出有效或无效的证据。性能没有提升时，也需要说明时间模式弱、历史受污染、模型已经捕捉相同信息等可能原因，避免将负结果隐藏。

工程意义是为网络检测与响应、运维分析提供可回放的验证工具：展示每分钟输入、异常分数、阈值、报警和真实标签，比较同一时段不同方法的误报与漏报。它能帮助分析人员检查方法的适用边界；本课题没有证据保证达到生产NDR能力、自动处置攻击或减少某一真实企业的损失。

## 5 现有研究不足与候选研究空白

目前可确认的是，不同研究的检测单位、训练污染、切分和阈值来源并不一致。一些通用时序方法使用逐点调整或测试最佳F1，一些网络方法按测试异常比例选阈值；这些结果不能无条件当作当前课题的在线部署性能。具体差异在单篇卡片中记录，不扩张为“全部已有研究存在泄漏”。

**Research Gap Candidate：**在选定的公开网络聚合数据及统一时间外推协议下，显式时间上下文对轻量AI评分的作用、正常负载变化下的误报行为，以及对应运行开销，值得通过受控实验进一步核查。该限定是否与已有方法重复，尚需精读TCI、RUIDS、Rényi动态阈值、UGR相关工作后确认。AE、滑动窗口、EWMA、评分相加和按时间切分本身均不能直接称原创贡献。

## 7 主要研究内容

### 7.1 数据与标签定义

拟先审计UGR16 FeatureData，检查来源、版本、哈希、字段、X/Y与时间戳长度、排序、重复、缺失分钟、标签计数与训练背景污染。作者仓库提供一分钟特征及日期/日内辅助信息；不同版本字段数和处理不同。[作者仓库](https://github.com/josecamachop/UGR16_FeatureData)。

二元标签候选为：**该分钟含本次任务选定的攻击计数时标为异常**；计数为零是否代表已确认正常、未知/未标记行为如何处理，必须依据该版本标签说明核实。标签Y只用于允许的训练筛选、验证及最终评价，不进入特征矩阵。类别、攻击发生时间不能作为可用行为输入。逐攻击类型评价仅在标签可靠且支持相应粒度时进行；分钟聚合报警不能自动定位IP或连接，也不能宣称识别零日攻击。

### 7.2 特征工程

| 特征层 | 拟使用内容 | 数据与因果性约束 |
|---|---|---|
| 原始聚合 | 作者提供的聚合计数、统计或编码特征 | 建立字段字典；“134维”仅对应特定版本，逐列定义未审计前不逐项编造 |
| 时钟上下文 | 日内分钟的sin/cos编码；经核验的工作日/周末 | 有真实日期与日内信息才用，不从行号虚构日历，不把无含义时间ID当连续数值 |
| 历史上下文 | 仅过去区间的均值/中位数、离散程度、增量与偏离程度 | 输入历史范围和更新顺序冻结，禁用居中平滑与未来点；缺失区间不能当连续分钟 |
| 其他数据的流特征 | 若以后采用流级数据，可审计时长、包数、字节数、包长、IAT、方向/协议等 | 不是UGR现有字段承诺；引入会改变检测单位，需变更数据与协议 |

候选连续字段按训练集统计清洗、转换和缩放，验证/测试沿用已拟合参数。不对全部数据先标准化，不用测试标签选特征。特征筛选、取对数和缺失插补均应记录适用列及原因，避免盲目对类别编码执行连续数值操作。

### 7.3 时间分析对象与算法

时间分析对象是正常记录的特征/总量如何随实际时间变化，以及当前向量相对近期已知背景的偏离。数据分析候选使用日内分组曲线、工作日/周末分布和自相关函数；自相关要求检查采样间隔与缺失。是否具有24小时周期由数据决定，不能预填结果。

用于检测的时间机制另作受控候选：过去窗口中位数与MAD形成稳健背景，或EWMA描述近期趋势。它们是已有统计方法，不是深度AI，也不自动证明能够区分业务高峰和攻击。先记录历史长度、异常污染更新策略、启动期和缺失处理；窗口长度不预设为“5分钟/12窗口”。

### 7.4 AI检测对象与算法

IF拟作为传统ML对照，用隔离路径给当前分钟向量异常排序；轻量全连接AE拟作为深度对照，学习特征组合并以重构误差输出分数。**检测对象是标签支持的异常分钟及其行为向量**，不是视频内容、网站真假或用户意图。模型输出是异常程度，是否报警还需要冻结阈值。

AE评分候选为变换后特征的平均平方重构误差；模型容量、损失、训练轮次、随机种子、早停和评分尺度后续记录。若通过已知正常标签筛选训练数据，应明确为正常样本训练/标签辅助的数据准备，不能笼统宣称整个链路完全无标签。混合背景训练时则需测污染敏感性。AE可能重构异常，单一大误差也可能来自正常分布变化，需要实验判断。[Kitsune方法](https://arxiv.org/abs/1802.09089)、[PyOD](https://www.jmlr.org/papers/v20/19-011.html)。

### 7.5 时间感知方法候选

当前只需从以下机制中选择一个作为最小受控验证，其他保留比较或扩展，不能同时堆入后宣称每个有效：

1. 加入时钟与历史特征，使相同当前行为在不同背景下获得不同评分。
2. 用仅过去形成的背景构造残差或偏离特征，再由IF/AE评分。
3. 保持AI评分模型不变，研究仅根据历史/验证信息调整阈值的影响。

若采用独立统计分数与AI分数融合，先定义共同检测单位、方向、尺度、训练/验证校准和参数，再登记为候选。若最终不采用融合，更新路线和消融图，不将Score Fusion写成已确认创新。时间信息、表示学习、阈值效果要分别比较。

### 7.6 原型系统

拟提供数据版本选择、实验配置、方法运行记录、历史Replay、分数与阈值时间线、报警/标签对照、指标比较及结果导出。逻辑模块为Data Loader/Preprocessor、Detector、Temporal Context、Calibrator、Evaluator、Result Store与展示层。研究输入、输出及错误状态写入需求、模块和测试追踪，不以增加软件产品数量体现AI含量。

Python研究模块为候选核心；前端Vue、应用后端Spring Boot、数据库均保持候选，按原型需要决定。P0不引入实时采集、在线重训练、Kafka、复杂分布式组件或LLM聊天功能。原型验证方法可运行和结果可追踪，不代替研究实验。

## 8 研究方法

文献研究按“问题—输入—时间—训练与标签—阈值—指标—代码—局限”矩阵核验；数据分析审计真实时间、标签及版本；机器学习实验先建立最低复杂度基线；对比、消融、参数与效率实验共享评价协议；工程验证检验Replay、配置恢复、结果一致与失败记录。

研究线与软件工程线保持映射：RQ产生实验需求；实验需要的输入输出形成模块职责；模块行为通过软件测试检查；研究结论由检测实验支持。页面显示正确不能证明算法有效，较高F1也不能证明系统可靠。

## 10 关键技术与实验协议

以真实时间先划分较早训练区间、其后验证区间、最后测试区间，再构造/分配样本和拟合变换。训练、特征选择、模型调参及阈值选择不得使用测试真值。共享历史上下文的规则必须事先冻结：允许在推断时使用已观测的过去输入；不允许读取未来输入或测试标签更新背景。若重叠窗口导致训练目标跨入验证/测试，需隔离或剔除边界窗口；缺失区间采取显式中断/掩码策略。

阈值政策候选为在验证集允许的标签预算下满足统一目标，或按无标签训练/验证分数分位数校准；选择哪一种后需全部方法一致执行。无标签分位数不等于已保证业务FPR。主结果禁止用测试异常比例、测试最佳F1或事后最优窗口选阈值；这些如用于方法审计，只能单独标明上界，不能与可部署主结果混排。

评分方向统一为越大越异常，训练/验证校准后再比较；可采用不同适配器，但保留原分数及转换。静态方法和时间方法保持数据、特征可得性、调参预算与评价单位一致，记录改变的唯一组件。

## 11 拟探索的特色与可能贡献

拟探索一个足够具体的时间机制，验证其在目标数据时间外推时对AI评分与正常高负载误报的作用，并报告召回代价与适用条件；形成阈值数据来源明确、无未来上下文、不同方法可比较的实验材料；建立可Replay与追踪的验证原型。

这些是候选贡献，不是已经获得的创新。按时间切分、采用AI或做可视化属于方法与工程要求。最终能否形成研究贡献，取决于相关工作差异、实验效果、可解释机制和独立完成的内容。与同届网络监测题目的边界仍需任务书确认，不能断言对方没有AI或只做阈值。

## 12 测试与评价方法

评价单位与输入保持一致。以分钟二元判断为例，TP为真实异常且报警的分钟，FP为真实正常且报警的分钟，FN为异常未报警，TN为正常未报警。

| 指标 | 定义/评价对象 | 解释与限制 |
|---|---|---|
| Precision | TP/(TP+FP) | 报警中有多少真实异常；无报警时记录分母及未定义政策 |
| Recall | TP/(TP+FN) | 异常分钟检出比例；测试区间无异常时不能输出伪Recall |
| F1 | 2TP/(2TP+FP+FN) | 综合误报与漏报，但不足以替代独立FPR/Recall |
| FPR | FP/(FP+TN) | 全部真实正常分钟中误报比例；不是1−Precision |
| AP / PR曲线 | 在同一测试集、未调整分数上计算 | 主排序指标候选为Average Precision；若另报PR曲线梯形面积，写明积分实现，不与AP混称 |
| 时段/负载分层 | 预先定义正常背景组后分别统计FP、TN、FPR等 | 分组边界由训练/验证正常数据决定，不用测试结果挑“表现好”的区段 |
| 检测延迟 | 标签支持的事件起点到首次报警的时间差 | 未检出另计；一分钟标签只能支持相应分辨率，不能声称毫秒攻击检出 |
| 处理效率 | 单记录/窗口推断p50、p95、吞吐、训练时间、峰值RAM/VRAM | 处理耗时和攻击检出延迟分开；记录设备、批量、预处理是否计入与CPU/GPU同步方式 |

具体实现参照[scikit-learn评价文档](https://scikit-learn.org/stable/modules/model_evaluation.html)。指标分母为零时按冻结规则显示N/A或警示，不静默以零代替全部无效情况。主结果保留逐点/逐分钟未调整结果，不能在区段中检测到一个点后把整段改为全部命中。事件覆盖可作为单独补充指标，写明事件合并规则。

对比对象初步为静态统计对照、IF、轻量AE及一个时间增强版本；额外已有Temporal方法需代码/数据适配可控才加入。消融去除时间信息或替换AI核心，其他条件不变；参数试验在验证阶段确定范围；效率试验固定设备与输入规模。重复训练记录随机种子；如估计时间数据置信区间，使用保持时间结构的块级方案而非默认独立同分布抽样。试验次数与资源预算后续冻结。

动态场景先分析公开数据自然变化；必要时对已确认正常片段构造受控变化，仅用于压力试验，标明人工构造、改变字段和标签假设，不当真实校园攻击。协议必须同时报告误报和异常漏报，避免“阈值抬高后FPR降低”冒充全面提升。

软件测试覆盖数据格式错误、时间逆序、X/Y错位、缺失、评分方向、可重放配置、指标算例和失败状态。OOM、输入异常及中断保存原因，不能当成成功完成的实验。每次实验保存数据版本、切分边界、变换参数、模型配置、种子、阈值来源、原始分数、预测与评价输出。
