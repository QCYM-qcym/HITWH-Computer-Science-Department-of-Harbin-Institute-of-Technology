本轮仅进行设计与文档化；未开展数据下载、模型实验或业务实现。题名为WORKING TITLE，模型、数据版本和性能指标尚未冻结。

## 1 阶段计划
正式截止日期、每周投入、阶段日期和预算均TBD，不使用固定周数作为承诺。
### Phase 0 前期设计
Goal：完成前期设计。Input：现有上下文与学校指南。Output：D01至D10、追踪矩阵及图集。Gate：DESIGN_REVIEW：覆盖完整且未知项有负责人。Risk：需求截断或范围膨胀。Fallback：先完成已知范围，图集缺失项补充后复审。日期：TBD。

### Phase 1 Data Gate
Goal：完成Data Gate。Input：数据候选与D03。Output：数据报告和冻结版本。Gate：DATA_GATE_PASS。Risk：时间或标签不可用。Fallback：替换数据或调整范围后复审。日期：TBD。

### Phase 2 Baseline
Goal：完成Baseline。Input：合格数据与统一协议。Output：统计和IF结果。Gate：BASELINE_PASS。Risk：协议泄漏或资源超限。Fallback：缩小时间段和批量。日期：TBD。

### Phase 3 AI Model
Goal：完成AI Model。Input：基线与候选轻量模型。Output：模型和Smoke报告。Gate：AI_MODEL_PASS。Risk：显存或兼容问题。Fallback：更小模型或CPU；保留AI研究要求。日期：TBD。

### Phase 4 Temporal Method
Goal：完成Temporal Method。Input：AI与时间证据。Output：时间候选及首轮消融。Gate：TEMPORAL_METHOD_PASS。Risk：窗口污染、无互补。Fallback：简化机制或保留负结果。日期：TBD。

### Phase 5 Experiment
Goal：完成Experiment。Input：冻结方法与矩阵。Output：对照、消融、效率和动态结果。Gate：EXPERIMENT_PASS。Risk：计算预算不足。Fallback：减少次要参数和P1数据，保留必要对照。日期：TBD。

### Phase 6 Prototype
Goal：完成Prototype。Input：稳定模型与输出契约。Output：查询及Replay原型。Gate：SYSTEM_PASS。Risk：多技术栈增加集成成本。Fallback：轻量单机实现替代多服务。日期：TBD。

### Phase 7 Evaluation
Goal：完成Evaluation。Input：实验和原型证据。Output：RQ结论、验收与局限。Gate：研究工程综合复核。Risk：外推过度。Fallback：限制结论范围并补充失败分析。日期：TBD。

### Phase 8 Paper
Goal：完成Paper。Input：设计与真实结果。Output：论文、任务书开题映射和答辩材料。Gate：FINAL_ACCEPTANCE_PASS。Risk：学校模板/截止日期未知。Fallback：提前准备结构，按正式通知调整。日期：TBD。

## 2 风险登记
| ID | 风险与触发条件 | 影响 | 应对与负责人 |
|---|---|---|---|
| R01 | 无法确认时间或标签 | 时间研究无依据 | 学生执行Data Gate，导师确认换数据或缩题 |
| R02 | 训练正常集污染或攻击日期代理 | 结论偏差 | 标签审计、条件说明、时间留出分析 |
| R03 | 时间融合无收益 | 原假设不成立 | 保留对照与负结果，分析失效，不伪造提升 |
| R04 | 8GB显存/驱动不满足 | 训练受阻 | 小模型、批量和CPU回退，资源实测 |
| R05 | 同届范围重叠 | 任务书边界不清 | 导师核对具体内容，不臆断对方无AI |
| R06 | 工期、预算不明确 | 无法承诺实验规模 | 用户补约束，按单次实测成本估算矩阵 |
| R07 | 多服务和数据库堆叠 | 研究时间被挤占 | 应用层候选化，先文件与单机链路 |
| R08 | 现场网络或设备不可用 | 演示失败 | 离线Replay与真实结果视频，提前演练 |
| R09 | 学校指南版本/专业补充未知 | 论文形式不合规 | 以已提供2022版提取，正式提交前核最新通知 |
| R10 | PHASE0请求在图集处截断 | 未知交付遗漏 | 保留截断证据，补文后检查覆盖 |

## 3 工期估算办法
Phase 2实测单次训练、推理、预处理与评估耗时，结合预定配置数、种子数、重跑余量和周投入估算；未知输入保留TBD。所有新增付费扩展另列模型、调用量、价格日期和预算审批，P0不依赖付费API。
## 4 变更管理
需求变化→影响RQ、数据、模块、测试的分析→新增决策→更新版本及追踪矩阵。旧材料只归档不删除。PHASE0完成不自动授权立即进入正式开发；下一阶段先Data Gate与最小试验。
## 5 开发入口条件
D02至D08经评审、关键数据条件明确、核心契约确定、实际资源可运行后安排相应实现；数据审计脚本与业务代码区分管理。当前仅文档和图源工具，不创建业务工程。
