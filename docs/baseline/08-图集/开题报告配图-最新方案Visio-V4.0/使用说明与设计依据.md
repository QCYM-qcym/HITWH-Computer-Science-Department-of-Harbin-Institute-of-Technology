## 设计边界

采用当前明确的Vue 3、TypeScript、Vite、Element Plus、ECharts前端，FastAPI、Pydantic、Uvicorn后端，以及独立Python工作进程。命令行与网页使用同一检测核心；首版为Windows单机、单用户、单任务。图中架构是拟实施设计，不表示已完成软件开发或实验验证。拓扑图沿用不列硬件型号和配置的要求。

第6图是依据3.5.2细化的**拟议逻辑ER**，不是已落地数据库反向工程：

- DatasetVersion保存数据集版本、来源、校验值、特征及独立标签文件位置。
- DataSegment归属一个版本，定义开始/结束时间与训练、验证、校准或测试角色；拟规定[start_time,end_time)边界，在boundary_config_json记录实际划分与有效分钟规则。
- Run归属一个片段，登记模型、配置、随机种子、代码版本及任务状态。首版单任务排队执行。复用模型及跨训练/验证/校准输入的文件引用先记入config_json，完整物理设计阶段再细化关联表或外键。
- Artifact归属一个Run，保存权重、缩放参数、阈值、配置、评分或指标文件的位置、格式及校验值。各产物按运行标识关联，避免把逐分钟矩阵塞入SQLite。
- Metric归属一个Run，scope区分整体、攻击或负载场景；未定义指标使用NULL并记录样本数和说明。拟采用UNIQUE(run_id,scope,metric_name)约束，避免重复汇总。
- 关系均为父记录1、子记录0..N；每个子记录的外键必填。DatasetVersion建议UNIQUE(name,version)，DataSegment需校验end_time>start_time，Run状态限定排队/运行/成功/失败。身份和版本一致性在详细设计时补充验证。**以上表名、主外键及字段名为本次图稿的设计细化，尚未冻结。**

历史构造仅使用过去H个有效分钟，先评分后更新，时间缺口重置；独立标签进入评价，不进入模型评分特征。第7图将轮询循环集中画在下方，实际在前端取得run_id后就可与后台运行并行。前端读取任务结果均经API完成。
