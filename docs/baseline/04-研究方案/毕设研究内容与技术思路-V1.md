# 毕设研究内容与技术思路 V1

指导教师：指导教师  
编制日期：2026年9月24日  
研究方向：时间感知网络流量异常检测  
版本状态：Working Title，方向已获导师原则认可，具体方案提交讨论。

本方案拟以公开网络流量数据为基础，研究时间动态信息与机器学习及深度异常检测结合后，对检测效果和误报行为的影响。研究交付以可复查的数据处理、方法比较、消融实验和失败边界分析为核心，原型用于结果验证与展示。现阶段先验证数据与基线，再确定时间建模方式和最终模型；尚无本课题实验结果。

## 1 暂定题目

《面向动态网络环境的时间感知流量异常检测方法研究》。当前为 Working Title，最终题目尚未冻结。导师原则认可的是研究方向，具体模型、数据版本、创新表述和实验范围仍需进一步论证。

## 2 研究背景

正常网络行为可能随日内时段、工作日与周末、业务高峰以及长期业务变化而改变。若检测器将历史正常分布视为固定不变，正常行为变化可能造成异常分数偏移和误报；直接放宽阈值又可能牺牲异常召回。因此，需要在明确时间信息与标签含义的前提下，研究时间上下文是否能补充静态特征模型，并量化效果与代价。

UGR’16 面向具有周期变化特征的网络入侵检测评价，其官方数据介绍及特征版本为时间感知实验提供了候选依据[1–2]。但某个数据集整体适合时间研究，不代表所选特征、子集必有稳定的24小时或周周期。本课题将先检查正常历史的时间规律及跨时段稳定性，不把预期现象写成已观察结果，也不将攻击日期差异直接解释为正常业务变化。

## 3 核心研究问题

**核心 RQ：**针对正常网络流量可能具有周期性和动态变化的特点，如何将时间动态信息与机器学习或深度异常检测模型结合，并评价这种结合在动态网络环境下对异常检测效果和误报行为的影响？

- **RQ1 时间规律：**所选正常流量是否具有可利用的日内、工作日与周末、长期变化规律？其强度与稳定性如何，哪些特征没有稳定规律？
- **RQ2 基线差异：**统计方法、传统机器学习和深度异常检测在相同时间协议下表现有何差异？正常行为变化时，误报和漏检分别怎样变化？
- **RQ3 时间信息作用：**固定数据、模型及校准预算，加入时间信息后，Precision、Recall、F1、FPR、PR-AUC及可测的Detection Latency如何变化？是否存在无收益或负收益条件？
- **RQ4 模块作用：**时间信息、深度表征与融合规则分别贡献什么？收益来自时间上下文、模型能力，还是阈值和参数选择差异？

上述问题是待验证的研究假设，不预设融合优于单模型，不以“时间感知”名称代替实验性定义。

## 4 主要研究内容

**数据预处理与时间特征分析。**核验时间字段、粒度、时区、覆盖、缺失和标签对齐，明确检测单位。优先研究可保留时间元数据的流量特征；在训练时段内分析日内分布、周期相关、工作日差异与长期变化，并在后续留出时段检验稳定性。

**异常检测基线。**建立静态统计方法、Isolation Forest和轻量AutoEncoder候选基线，统一输入特征、训练信息和评价协议。AutoEncoder首先作为深度对照；最终深度模块仍可根据文献、资源和最小运行结果在AE、VAE或轻量时序模型中选择，不同时要求复现所有模型。

**时间感知AI方法。**考察历史滚动统计、日内时间编码、同时间上下文等候选机制，与学习式异常分数结合。先选择一种可解释的时间机制验证，再决定采用分数级融合、时间特征输入或其他有文献依据的方式。复杂结构必须由研究问题和对照结果支撑。

**实验评价。**开展对比、消融、参数敏感性、效率及动态场景实验。保留单模型和简单规则等强基线，报告误报、漏检、延迟、资源和失败案例，不仅报告最优F1。

**验证原型。**形成按时间重放数据、展示时间行为和异常分数、追溯告警及实验结果的轻量原型。界面依托同一套实验输出，服务于证据解释和工程验证。

## 5 技术路线

整体流程为：公开流量数据 → 时间与标签审计 → 明确检测单位 → 时间顺序划分训练、验证、测试 → 仅训练段拟合预处理 → 时间分支与AI分支 → 分数校准及候选融合 → 固定判定规则 → 顺序评价与原型重放。

时间分支从当前可知的时间上下文和历史观测构造Temporal Score；AI分支从流量特征学习正常行为表征，产生AI Anomaly Score。候选融合先统一分数方向和尺度，再比较简单等权规则与验证段确定的融合规则，最后输出正常或异常判定。这个双分支流程是V1的研究方案，不是已经确定有效的最终架构。

每个时间点先使用既有历史完成评分，再按预先规定的规则更新状态；测试标签不得用于选择“正常样本”来更新基线。训练集、验证集和测试集按时间隔离，跨边界窗口及重复会话单独处理。归一化、缺失值填补、模型参数只能在训练信息范围拟合；阈值、融合权重和选择策略在验证阶段冻结，不能根据测试集最优结果倒推。

若采用一分钟聚合数据，分数与标签都以相同时间窗为单位；若采用流级数据，则另行明确流特征完成时刻。不同粒度下的指标不混报。当前不承诺在线实时部署或自动重训练。

## 6 AI技术定位

AI承担从网络行为特征中学习异常表征和产生异常分数的核心任务。统计方法与时间基线提供可解释对照，机器学习和深度模型提供另一类建模能力；两者是否互补须由消融实验判断。原型不以附加聊天功能体现AI含量。

Isolation Forest用于传统ML基线，AutoEncoder用于轻量深度基线及复现候选；VAE和轻量时序模型作为待评估类别。模型选型遵循方法相关性、数据适配、可信代码、评价协议和本机资源五项条件。P0不依赖大型LLM训练、多GPU、昂贵云GPU或企业内部数据。

## 8 实验设计

**对比实验。**在统一数据和时间划分下比较静态统计方法、Isolation Forest、AutoEncoder、经筛选的已有方法及时间感知候选法。公平性包括相同检测单位、特征可用信息、调参预算、阈值校准方式与异常标签定义；原论文原协议复现与本课题统一协议结果分开报告。

**消融实验。**设置AI Only、Temporal Only、Temporal与AI的简单组合，以及完整候选融合。双分支同时输出不构成独立检测器；组合组必须给出明确判定规则，例如校准后固定等权融合，再与候选融合比较。需要时进一步去除周期编码、历史更新或深度表征，保持其余条件不变；最终消融项随实际方法冻结。

**参数敏感性。**在预设范围内研究Window Size、Fusion Weight和Threshold。参数范围与主要工作点先由训练/验证确定；测试集只用于最终报告，不能以敏感性实验名义重新选取测试最优方案。

**效率实验。**分别记录训练与推理耗时、预处理与历史更新开销、CPU/RAM/GPU/VRAM峰值及磁盘增量。按相同输入规模、设备、批量和预热条件比较，单样本推理耗时不能替代事件检测延迟。

**动态场景实验。**在数据确有覆盖的前提下，比较日内时段、工作日与周末、不同时间阶段及可核实的正常流量变化。若另构造受控变化，记录构造规则、种子和标签保持条件，单独标明其合成性质，不宣称为真实业务漂移。没有概念漂移真值时不强行报告漂移检测成功。

正式实验按时间块或实体等合理单位分析波动，不将高度相关的相邻流视为独立重复。多次训练的模型保存预先确定的种子与全部结果；方法无提升时，分析时间规律、标签、窗口污染、阈值和融合校准，而非只保留成功运行。

## 9 评价指标

正类预定义为异常，所有TP、FP、TN、FN使用同一检测单位。

| 指标 | 定义与使用边界 |
|---|---|
| Precision | TP / (TP + FP)，同时报告告警数及正类比例 |
| Recall | TP / (TP + FN)，必要时按攻击类型分层 |
| F1 | Precision与Recall的调和平均，必须注明阈值确定方式 |
| FPR | FP / (FP + TN)，重点报告正常流量变化前后和各时段误报 |
| PR-AUC | 在异常稀少条件下评价连续分数；明确积分算法，Average Precision单独命名，不混为同一个数值[6] |
| Detection Latency | 事件开始到首次有效检测的时间；需要事件起点与告警对应关系，缺少则标不可评价，漏检事件另报 |
| ROC-AUC | 可作补充，不取代PR-AUC、FPR与阈值下结果 |

分母为零时按预注册约定报告NA或明确的库行为，不能记作完美检测。聚合窗口须说明时间分辨率和告警可用时刻；一分钟数据不能支持无依据的毫秒级事件检测结论。攻击比例、时间段样本数和异常数量随指标同时报告。

## 10 原型系统

原型读取冻结数据和模型配置，按时间重放Traffic Timeline、Dynamic Behavior、Temporal Score、AI Anomaly Score、融合判定、告警、Ground Truth与实验图。每个结果可追溯数据版本、模型版本、参数与运行记录；标签仅在评价展示层揭示，不进入实时评分输入。

P0以离线实验和可重复重放为主，不将在线抓包、多租户管理、复杂微服务和高可用部署列为前置。现场展示依次准备本地轻量计算或预建结果、明确标注的历史Replay、真实实验图和视频备份；回放不冒充实时推理，演示备份不替代研究阶段的真实运行。

已知同届课题为《网络流量基线监测系统设计与实现》。本课题拟突出AI异常检测方法与实验研究，重点交付时间信息分析、学习式异常表征、模块作用验证、动态场景评价及误报行为解释；原型作为这些研究结果的验证载体。

## 12 当前风险与范围控制

**数据时间结构风险。**所选特征或子集未必有稳定周期；先做Data Gate及训练段规律分析，若证据不足则转向近期历史上下文或重新讨论范围，不预设24小时/周周期。

**模型复现风险。**可信论文或代码不等于本机跑通；先完成统计、IF及一个轻量AE的最小运行，记录版本、预处理、资源和失败。最终深度模型经文献、基线和Smoke Test后确定。

**时间方法有效性风险。**时间机制可能无收益，甚至因窗口污染、业务变化或证据错配增加误报。通过同模型对照、简单滚动基线、消融与分时段分析区分原因，不通过增加复杂模块掩盖负结果。

**Research Gap风险。**周期建模、动态阈值、AE与分数融合均已有研究，不能直接称为创新。研究空间需围绕具体数据条件、信息边界、对照方法和失效场景继续查新；V1仅提出待验证问题。

**工程与工期风险。**控制为单一主数据版本、一种主要时间机制、一种深度候选和必要对照。第二数据集或模型为扩展，持续在线学习和复杂平台不进入基础闭环。开发机为（本地设备参数）、（本地设备参数） RAM、（本地设备参数） 8GB专用显存；规格不等于可运行性，兼容性、峰值和耗时需实测。正式截止日期及每周投入尚未确定，不承诺固定完成日期。

## 13 下一阶段

**第一步，Data Gate。**优先审查UGR’16 FeatureData具体变体及完整时间元数据，建立数据说明、标签映射、时间覆盖和划分记录。验收目标是证明所选文件支持当前研究问题，不是只确认文件可读取。

**第二步，Baseline Smoke Test。**在固定小子集上验证统计方法、Isolation Forest及一个轻量AE的预处理、训练、评分和指标计算链，保存环境、资源和预测记录。通过标准是标签/输入隔离、因果时间顺序、指标可复算与运行资源可承受；不要求方法必须取得高分或融合必胜。

**第三步，论文精读与方案修订。**围绕数据质量、时间建模、深度异常检测及阈值/评价精读已有文献，确认复现主锚点和最简单的有力对照。根据Data Gate、Smoke Test和导师反馈形成V2，再冻结数据、模型、主要实验与题目表述。

预期阶段材料为数据适用性说明、可复跑基线记录、研究问题与实验映射、V2技术路线。正式文档呈现可独立阅读的结论和方案，失败、修改原因及完整原始记录另在研究知识库持续留存。
