# 实验设计与验收方案

版本：V0.2　日期：2026-09-27　状态：DRAFT FOR REVIEW；增加软件测试/研究评价双轨、研究不变量测试及按攻击面控制的安全范围；未运行测试或实验

课题题名：面向动态网络环境的时间感知流量异常检测方法研究（Working Title）。

事实来自既有记录标为FACT；DECISION表示当前范围决策；HYPOTHESIS为待检验假设；CANDIDATE为候选方法；待确定事项均按注册表编号管理；RISK为尚未证实的风险。所有模型与实验结果均未运行。

## 1 评价边界与基线

本方案分为Research Evaluation和Software Acceptance。前者回答方法是否有效及何时失效，后者验证实现是否满足需求。系统能运行不能推出算法有效，模型没有提升也不能通过删除负结果形成结论。

DECISION：研究主体为AI异常检测方法、时间动态信息与实验评价，系统仅作为工程验证载体。同届课题目前仅知题名，不据此判断其是否采用AI。

CANDIDATE：统计稳健评分、Isolation Forest和轻量AutoEncoder构成初始对照。相关已发表强基线待精读和代码核验后决定，不能只与人为设置的弱阈值比较。正常训练条件、特征信息和调参预算应一致。 [TBD-007] [TBD-011] [TBD-013] [TBD-019]

## 2 对照实验

E02比较统计、传统ML和AI；E03固定AI、数据和校准机会，比较有无时间信息。记录训练/验证/测试边界、样本数、类别比例和所选阈值规则。不同原论文协议的复现结果与本项目协议结果分别报告。 [TBD-007] [TBD-026]

## 3 消融实验

E04至少包括AI-only、Temporal-only、等权融合及候选融合。若加入日历、历史更新或其他机制，再逐项移除，保持其余条件相同。每组均输出连续分数及独立验证所得阈值。 [TBD-006] [TBD-007]

## 4 参数敏感性

E05考察历史窗口、融合权重及阈值工作点。范围、种子与运行预算TBD，在验证阶段登记并冻结。测试图用于分析，不再用于选择最终模型。为参数搜索付出的额外预算应计入方法成本。 [TBD-006] [TBD-007] [TBD-011] [TBD-015]

## 5 效率实验

E06在相同设备和固定输入规模下，分别测量预处理、训练、推理、历史更新及结果写入耗时，记录CPU、内存与专用显存峰值。批大小、预热、重复次数和计时边界须明确，门槛TBD。 [TBD-008] [TBD-008]

## 6 动态场景评价

E07按可信时间分组评价正常变化、稳定时段及异常区间，并报告组内数量。真实采集变化与人工扰动分开分析。人工扰动需说明构造规则、强度和标签是否仍成立；不得将其称为真实校园或B站攻击。

## 7 指标口径

指标定义见表7-1。TP、FP、TN、FN统一基于冻结检测单位。正类为异常；事件级与记录级结果分别统计，不能混用分母。 [TBD-016]

**表7-1  核心评价指标**

| 指标 | 定义 | 解释与限制 |
| --- | --- | --- |
| Precision | TP / (TP + FP) | 报警中真实异常的比例 [TBD-026] |
| Recall | TP / (TP + FN) | 真实异常被检出的比例 [TBD-026] |
| F1 | 2 × Precision × Recall / (Precision + Recall) | 精确率与召回率的折中 |
| FPR | FP / (FP + TN) | 正常记录被误报的比例 [TBD-026] |
| PR-AUC | 按冻结计算规则计算精确率召回率曲线面积 | 报告实现口径，不混同Average Precision |
| Detection Latency | 事件开始到首个匹配告警的时间 | 起点与匹配规则不可信则N/A |

零分母、缺少类别或不具备延迟证据时标记N/A。PR-AUC算法口径预先确定；ROC-AUC按需要补充。不得采用未披露的整段异常补齐策略。 [TBD-023]

## 8 可复现性

每个Experiment ID关联Dataset Version、Code Version、Model Config、Seed和Environment，并保存特征变换、切分清单、校准参数、阈值、预测及指标。原始数据、训练产物和派生文件计算哈希；随机与GPU非确定性容差TBD，需在重复运行前登记。 [TBD-007] [TBD-013]

结果应能从同一输入和配置重新生成。记录全部预定种子和时间块波动，不仅报告最好一次。取消或失败的运行不覆盖，数据变更、调参和结果排除均说明理由。 [TBD-015] [TBD-020]

## 10 验收门槛

Gate表示证据满足预定退出条件，不表示方法必然优于基线。前三项门槛定义如下，当前均为NOT_RUN。

### DATA_GATE_PASS

Entry Criteria：候选来源和数据设计已评审。Procedure：校验载荷、字典、时间、标签及切分。

Evidence：哈希、质量报告、时间审计及资源日志。Exit Criteria：数据语义明确且可支持所选时间机制，解析资源可接受。

### BASELINE_PASS

Entry Criteria：数据Gate通过，协议登记。Procedure：运行统计与IF并复算指标。

Evidence：配置、预测、指标及重复运行记录。Exit Criteria：基线闭环正确可复现，无已知泄漏。

### AI_MODEL_PASS

Entry Criteria：基线通过，候选训练配置登记。Procedure：训练、重载、评分并测量资源。

Evidence：模型、损失记录、重载测试、资源日志。Exit Criteria：学习式模型可运行可评价；不要求性能优于基线。

数据Gate包含文件完整性、字段语义、时间审计、所选时间机制适用性及切分泄漏检查。若周期不存在但近期上下文可用，可修订研究范围后重新评审；不能以更换状态名绕过数据缺陷。 [TBD-013]

## 11 验收证据与追踪

### TEMPORAL_METHOD_PASS

Entry Criteria：AI可用，时间机制有依据。Procedure：核验因果窗口、校准、融合及初步消融。 [TBD-006]

Evidence：状态轨迹、评分明细、消融结果。Exit Criteria：行为正确且可复现；无增益如实进入研究结论。

### EXPERIMENT_PASS

Entry Criteria：实验矩阵、方法与超参选择规则冻结。Procedure：执行对照、消融、敏感性、效率和动态评价。

Evidence：完整运行集合、图表、配置与负结果。Exit Criteria：能够按统一口径回答RQ，局限与未支持假设已说明。

### SYSTEM_PASS

Entry Criteria：核心模块集成，验收数据及环境登记。Procedure：走查数据至回放链路，注入非法输入与运行失败。

Evidence：功能报告、日志、截图和演示记录。Exit Criteria：P0需求满足，失败不冒充成功，交付模式明确。

追踪规则：每项FR-nnn对应TC-FR-nnn；模块归属沿用HLD。每项NFR-nnn对应TC-NFR-nnn。实际测试记录必须写前置条件、输入版本、步骤、预期、实际结果和证据路径，不能用设计描述替代执行记录。 [TBD-022]

失败先记录原因、影响和修订方案，再独立复验。Gate由NOT_RUN转为PASS必须附证据；不能仅因生成文档或图表而通过。最终论文与交付验收还应覆盖学校规范、答辩演练和结论边界。 [TBD-009]

## 14 双轨测试策略

功能验收与研究评价分开报告。软件测试回答实现是否遵守契约；研究评价回答候选方法在明确数据/协议下提供什么证据。任何一个都不能代替另一个。

| Software Testing类别 | 本课题重点 | 典型证据 |
|---|---|---|
| Unit | 时间排序、窗口边界、评分方向、指标公式、配置校验 | 固定小样本断言与复算记录 |
| Integration | Data Loader→Processing→Detector→Result Store；完整配置与版本引用 | 端到端工件清单及失败状态 |
| API（若保留服务/API） | 非法参数、缺字段、状态/错误响应、授权边界 | 请求/响应样例与断言；不默认强制Web API |
| System | 用例UC-01至08的本地流程和状态 | 测试记录、截图与产物版本 |
| Failure | 坏文件、缺字段、OOM、取消、中断、存储失败和重试 | Defect ID、日志、修复与回归证据 |
| Performance | 固定设备/规模/预热下的时间、内存、专用显存 | 环境、方法、重复测量与原始日志；门槛TBD |
| Deployment | Native候选、断网、GPU不可用、重启恢复和Replay | 四级演示演练记录 |

| Research Evaluation类别 | 关键检查 |
|---|---|
| Data Validation | Schema/时间戳/缺失/连续性/标签/许可；不可用数据不进入训练 |
| Baseline Validation | 基线分数方向、同数据切分和指标手算核对 |
| Comparative Experiment | 相同数据单位、切分、调参预算与报告协议 |
| Ablation Study | AI-only、Temporal-only、Temporal+AI及候选Fusion；没有独立模块时调整设计 |
| Parameter Sensitivity | 只用预定验证协议选择配置；测试结果不反向调参 |
| Efficiency | 可复现计时边界、硬件状态、峰值RAM/VRAM及成本 |
| Temporal Scenario | 时间留出、日内/周内等分组仅在数据支撑时使用；报告样本量/局限 |
| Reproducibility | Dataset哈希、环境、代码版本、参数、seed、产物和指标重算 |

## 15 研究关键不变量测试

| 不变量 | 验证动作 | 通过证据 |
|---|---|---|
| Timestamp ordering | 输入打乱/相同时间戳样本，核查稳定排序及时区单位 | 顺序、重复与断点审计报告 |
| Temporal leakage | 在窗口边界加入未来记录，比较当前之前的输出不应变化 | 因果边界单元测试与时间切分记录 |
| Normalization leakage | 改变测试分布，不重拟合训练变换 | 训练拟合统计量哈希不变、测试访问记录 |
| Model reproducibility | 固定依赖/seed/config重跑并重载 | 分数差异在预设容差内、两次manifest |
| Anomaly score validity | 合成可手算的小样本核对方向/范围/异常值处理 | 单元测试与人工复算 |
| Metric correctness | 边界混淆矩阵、单类和零分母样本 | 手算值及N/A策略一致 |
| Config consistency | 同一配置Hash关联模型、预测、指标和图表 | 工件清单无断链 |

## 16 安全与缺陷边界

若最终采用Web UI/API，只按真实输入/接口/账号攻击面设计参数校验、权限及错误处理。SQL Injection、XSS、越权不自动成为P0；只有引入对应数据库、Web输出或账号边界并被需求接受时才补用例。漏洞测试不能触达未授权外部网络或真实流量。

缺陷分类、Severity、Root Cause、Fix、Verification、Status及关闭条件见`07-测试与验收/Defect-Register.md`。研究假设无增益、数据不适用与CODE_BUG分别登记；不能用修指标、删失败run的方式通过Gate。
