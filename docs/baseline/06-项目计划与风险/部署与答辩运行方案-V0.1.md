# 部署与答辩运行方案 V0.1

状态：逻辑候选，不是生产拓扑。优先单机Windows开发/答辩方式；已知开发机规格只是设备信息，不是依赖、GPU调用或现场设备测试通过。答辩电脑、联网、安装权限、WSL/Docker和API可用性仍待确认。

## 逻辑拓扑

Browser/Presentation（Vue候选或轻量本地界面）→ Application/Experiment Control（Python优先候选，Spring Boot仅候选）→ Python Research/AI Service → Dataset + versioned result/artifact storage。UGR'16为主候选、CICIDS2017为辅助候选；Live Traffic Source标为FUTURE/OPTIONAL，不进入P0。具体图见FIG-06；具体产品和服务边界待Technology Decision Matrix及接口证据决定。

## 四级演示降级

| Level | 演示方式 | 前置条件 | 断网/GPU/API失败时 |
|---|---|---|---|
| 1 完整在线Demo | 如最终确有在线数据源/外部服务，则展示实时输入、检测和结果 | 已授权来源、联网、运行服务和目标设备经过排练 | 任一前置失败即降级；在线能力不作为P0成立条件 |
| 2 本地完整Demo | 本地轻量模型或可运行模型、预建索引/结果，现场触发检测/比较 | 本地模型/依赖/结果版本固定；离线走查通过 | GPU不可用则先试CPU/轻量；模型不可运行切Level3 |
| 3 历史流量Replay | 对公开历史样本按时间播放，并显示该样本真实已生成的时间线、分数、标签与事件 | 记录与运行/模型/数据版本关联；明确“历史重放” | 断网可用；GPU故障可读既有真实结果；Replay不得混淆成实时检测 |
| 4 预生成结果 + 视频备份 | 使用同一次真实实验的冻结图表/日志/录屏说明方法和指标 | 真实Run ID、原始工件和报告可查；明确静态展示 | 作为最低现场保障；不能伪造曲线、预测、标签、模型效果或称实时 |

优先保证2级离线可演示，3/4级确保答辩现场故障时仍有最低可审证据。数据标签应与Detector推理输入分开显示；只有真实运行生成的结果才可标注“检测结果”。

## 准备与验收清单

1. 核实答辩设备、操作系统、安装权限、联网/API策略和可用空间。
2. 固定数据/模型/配置/代码版本与运行Manifest；准备不含密钥的本地备份。
3. 排练成功、空数据、无GPU、断网、输入错误与现场重启场景。
4. 现场显示Traffic Timeline、Temporal Pattern（若Data Gate支持）、Baseline、AI Score、Ground Truth（只用于评价/展示）、Detection Event、Method Comparison及Ablation Result；每个视图标注数据/Run ID和是否Replay。
5. 验收者可沿输出回到数据版本、配置、模型、时间切分、指标定义和实际Run。

## Docker与外部资源

Docker是可选候选，仅当环境复现、演示部署或依赖隔离有实证收益时采用；先检查WSL/Docker环境及GPU/挂载，再评估复杂度。当前不宣称Docker部署已确定或可用。无Requirement不加云服务器、域名、备案、Kubernetes、Redis/Kafka/Gateway/Nginx；P0不依赖商业模型API/云GPU。任何付费或云资源进入P1/P2前单列价格日期、调用量和预算。
